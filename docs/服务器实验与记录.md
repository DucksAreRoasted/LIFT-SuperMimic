## 1. 首轮实验定位

当前代码是固定权重 Q／BPTT 双梯度骨架。可信度权重和自适应时域尚未实现。本轮使用同一个已有 SuperMimic 检查点，比较继续训练的更新机制；不是从零训练对照，也不是完整论文指标复现。

实验程序从指定检查点读取机器人与网络配置，因此可以使用服务器上的 G1 或 R1 检查点，无需沿用本地路径。选中的动作 NPZ 必须对应同一机器人、关节顺序与重定向版本。第一轮仅支持单 GPU，方法与种子顺序执行。

| 方法名 | Actor 更新 | 其他说明 |
|---|---|---|
| `supermimic` | 原确定性 BPTT＋原 V critic | 加载已有均值、世界模型和 V；采用当前协议的匹配预算，不冒称原论文训练超参 |
| `q_only` | 随机 Actor 的 SAC／Q 梯度 | 仍训练世界模型，作为共享训练循环下的梯度消融；不是计算精简后的标准 SAC |
| `bptt_soft` | 随机 Actor 的 soft BPTT | Q 学自实际仿真数据并提供末端值，Actor 动力学权重为 1 |
| `dual_fixed` | Q＋soft BPTT，默认各 0.5 | 同快照融合后一次 Actor step |

原 SuperMimic 保留其额外动作噪声；随机 Actor 三组由高斯策略提供采集噪声，不叠加原动作噪声。两个随机单分支用于分离随机策略、soft 目标和融合带来的影响。新分支的 Q 初始未训练，原基线已有 V，这个初始化差异会写入说明，早期退化不能直接解释为融合无效。

LIFT 原有 locomotion 指标与本轮 mimic 任务不可直接横向排名；MPG／AGPO／HDPI 式权重和可信度方法还没有接入，后续在同任务同预算下新增，不将现有四组称为完整科研基线集合。

## 2. 在服务器使用统一 uv 环境

本仓库已经包含 `baselines/supermimic/` 与根 `third_party/`，无需另行克隆基线或手工设置 `PYTHONPATH`。在服务器本项目根目录执行：

```bash
uv sync --extra train --locked
CHECKPOINT=/server/path/existing_supermimic_checkpoint.pt
MOTIONS=/server/path/retargeted_npz_for_the_same_robot
CUDA_VISIBLE_DEVICES=0
export CUDA_VISIBLE_DEVICES
```

启动器默认使用当前 uv 环境的解释器，基线和 TADG 共用相同依赖和锁文件。详见[代码整合与 uv](代码整合与uv.md)。数据和检查点仍使用服务器已有文件。

## 3. 第一轮服务器短运行

```bash
uv run --extra train --locked python scripts/run_suite.py \
  --checkpoint "$CHECKPOINT" \
  --motions "$MOTIONS" \
  --protocol configs/experiments/server_smoke.json \
  --methods supermimic dual_fixed \
  --seeds 0 \
  --output /server/results/tadg_first_run
```

此配置只有单动作、64 环境、80 次向量环境步、H=4、100 步封顶评估，关闭编译以减少首次编译等待。它是实际训练链的短运行，不能据此评价学习速度或研究优势。

输出目录必须是新目录，防止覆盖旧实验。失败时默认停止后续方法并保留错误栈；需要继续记录其他方法时显式加 `--continue-on-error`。控制台日志位于 `seed_0/<方法名>/console.log`。

## 4. 小规模对照

确认第一轮能完成后，由用户在服务器运行：

```bash
uv run --extra train --locked python scripts/run_suite.py \
  --checkpoint "$CHECKPOINT" \
  --motions "$MOTIONS" \
  --protocol configs/experiments/pilot.json \
  --methods supermimic q_only bptt_soft dual_fixed \
  --seeds 0 1 2 \
  --output /server/results/tadg_pilot_v1
```

默认每组 2000 次向量环境步、256 环境，即计划 512000 条训练转移；4 方法×3 种子顺序执行。动作集覆盖行走、跑步、舞蹈、跳跃和起身。动作名不匹配时请在运行前修改协议文件并保存为新版本，程序不会按运行成绩自动删片段。

所有方法采用同一预训练来源、动作清单、环境数、WM 批量、想象时域和训练步数。Q／V 更新本身不同，因此同时记录实际更新次数、想象样本量和耗时；同交互预算不等于同计算预算。

`--steps` 可以覆盖训练步数；只生成配置与命令可加 `--dry-run`。dry-run 也建立新结果目录，真正启动请另选一个新目录，不复用 dry-run 目录。

```text

  evaluation_curves.csv         多检查点的统一评估曲线数据
  aggregate.json                相同训练步数的多种子统计与配对差值
  seed_0/dual_fixed/
    console.log
    config.json
    resolved_config.json
    run_metadata.json           服务器环境、包版本、GPU 与预训练来源
    events.jsonl                每次 WM／Actor 更新、评估、资源和保存事件
```

`recent_replay.pt` 仅保留最后一段环形 buffer，不是完整训练转移流。`traces.npz` 是统一评估过程的抽样状态、动作、奖励与误差，默认 pilot 每 10 步取一次。若后续需要全量 transition 流，应另接分片记录，不能将现有快照误称为全量数据。

## 6. 比较指标

- **任务表现：**归一化回报、失败率、参考完成比例、封顶评估标志、各奖励项。
- **原始跟踪误差：**根部位置／姿态／heading、全局及重锚定身体位置、身体朝向、线／角速度、关节角和速度 RMSE。
- **动作行为：**动作均值幅度、最大幅度、相邻动作变化、软关节限位超出比例与幅度；随机组另外记录策略标准差和采样熵。
- **学习信号：**世界模型多步误差与梯度，Q 值／target／TD 残差／分歧，Actor 两条梯度范数、夹角、权重与目标。
- **样本与计算：**实际训练转移数、独立评估转移数、Actor／Q／WM 更新数、想象步数、训练初始化／更新／保存／评估时间、GPU 显存及定时资源记录。

Q 专属、随机策略专属或双梯度专属指标在原基线中没有对应量，应标为不适用，不填成零。

当前未记录机械能耗、真实接触冲量和真机安全指标，不能以动作幅度代替能耗结论。GPU 功率是资源采样，不能在没有处理其他进程影响的情况下声称精确的训练能耗。

## 7. 统一评估口径

训练前、每次定期保存及训练结束时，对同样的参考动作、初帧和评估随机种子执行均值策略。评估关闭动作／观测噪声、reset 噪声和域随机化；评估 RNG 保存恢复，避免改写后续训练随机序列。

指标使用该次动作后、自动 reset 前的状态，对应本次转移的参考目标；终止状态通过 recorder 保留。奖励分项来自仿真奖励记录，原始误差通过公共 FK 与参考动作计算，避免不同算法采用不同口径。

pilot 默认每条评估最多 1000 步，**未摔倒而达到上限不等于整条动作成功**。`evaluation_capped`、失败和完成比例分开报告；正式整段基准请将 `eval_max_steps` 设置为 `0`，并以新协议版本执行。

`norm_return` 按实际执行步数归一化；`window_norm_return` 按预定评估窗口长度归一化，避免提前失败后的高短时回报掩盖失败。两者和失败率一起看，不挑其中一项单独宣称优势。

这些公共评估入口已通过 R1 单动作短运行；服务器首次长运行仍需关注终止状态和参考时间对齐。原 `eval_benchmark.py` 仍可作为额外的既有评估口径，不能把新入口的数值自动当作已对齐论文报告。

## 8. 汇总与科研结论

批量任务完成后自动生成汇总；也可独立执行：

```bash
uv run --extra train --locked python scripts/summarize_suite.py /server/results/tadg_pilot_v1
```

失败、未完成和超时组保留在 `summary.csv`。多种子汇总只按相同最后评估步数分组，配对比较使用相同种子和步数；单种子结果不报告成稳定改进。

已有预训练计算成本不计入本轮继续训练预算，所有组共用并在元数据注明。当前研究问题是固定双梯度在共同起点上的表现；即便其优于原基线，也还不能据此声称可信度机制或自适应时域有效。
