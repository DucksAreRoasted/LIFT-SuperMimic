# 基于最新四组数据的稳定性修复尝试

更新：2026-11-07。依据 `outputs/server_20261107/analysis/analysis.json` 和对应原始日志。本文区分数据结论、已经实现的防护，以及尚未证明的训练效果。既有实验配置、源码快照和未提交修改均保留；没有部署服务器或启动新一轮 5000 步训练。

## 1. 最新数据支持什么判断

- Q-only 在第 2500 步局部校准通过，首次 Actor 更新为 2502 步；到 3000 步全动作失败，3094 步 Q 梯度范数非有限而退出。
- 固定融合在第 1500 步通过校准，1502 步开放 Actor；2000 步已经全动作失败。后期梯度余弦接近 -1。
- 固定方差确实生效，sigma 约 0.1003；均值动作仍可达到极端幅度。因此不能将当前问题归给探索方差膨胀。
- 放行时同时开放 Actor、切换 Q 的标签来源，从 V 监督转到 Bellman 自举。该混合改变没有建立独立因果对照。
- 原 SuperMimic 继续训练的学习率、时域、批量、优化器恢复方式与原 51350 步检查点的原生训练状态不同，原生继续训练对照尚未验证稳定。

这些证据支持先限制 Actor 的可观测漂移、拆分 Q 标签切换，再验证原生恢复；不能据此宣称已找到唯一根因。

## 2. 可复现的具体失效模式

`outputs/stability_repair_20261107/reproduce_actor_drift.py --legacy` 使用实际 `dual_actor_step`，以一个线性 Actor 和固定正向 Q 导数构造最小问题。100 次 Adam 更新的所有梯度均有限，并已做全局裁剪，但原 Actor 均值仍漂移约 2.0，超过设定的 0.1 邻域。

同一脚本默认启用新防护后，实际均值偏移被保持在 0.1 内。它复现和修复的是“梯度裁剪不能限制动作输出漂移”这个失效模式，不是三行代码证明了完整人形机器人任务已恢复。

## 3. Actor 更新的局部回退检查

新增 [actor_safety.py](../src/tadg/actor_safety.py) 的 `ActorStepGuard`，接入 [gradients.py](../src/tadg/gradients.py) 与 [trainer.py](../src/tadg/trainer.py)。

每次 Actor 更新使用固定的当前 replay batch，先记录当前均值和冻结老师的均值。求梯度、裁剪后：

1. 保存 Actor 参数和完整 Adam 状态。
2. 尝试一次 Adam step，重新计算该 batch 上的均值动作。
3. 检查候选输出有限、相对更新前的动作 RMS 变化，以及相对原老师的最大逐元素偏移。
4. 超限时恢复参数和 Adam 状态，减半本次学习率重试。
5. 达到最多回退次数仍不通过，就完整拒绝该次 Actor 更新；Q/WM 已完成的更新保留。
6. 接受后恢复外部学习率调度值；Adam 的动量和步数只提交实际接受的一步。拒绝的尝试不会积累 Adam 动量。

本次短验证的初始工程界限是：动作变化 RMS ≤ 0.01、相对老师最大偏移 ≤ 0.1，最多 8 次回退。单位为归一化动作，不是弧度。这些值尚未通过性能调参验证。

新增配置字段（位于 `q_only` / `bptt_soft` / `dual_fixed` 方法块）：

```json
{
  "actor_max_change_rms": 0.01,
  "actor_max_teacher_deviation": 0.1,
  "actor_max_backtracks": 8
}
```

两个界限默认都为 0，保留旧配置行为；启用时必须同时为正且有冻结老师 Actor。改动不会向原预训练动作接口直接套 tanh，也不会更改保存的策略结构或破坏既有均值评估入口。

**限制：这是当前检查 batch 上的局部约束，不是全状态空间保证。** 新状态上的漂移仍可能出现，边界也可能使学习停滞。接受步数、拒绝步数和回退倍率必须与成绩一起报告。

日志新增 `actor_rejected` 事件、`actor_rejected_updates` 计数及 `actor_mean_change_rms`、`actor_teacher_deviation_max`、`actor_step_scale`。实际 Actor 更新数只增加接受的步数；拒绝 BPTT 更新时仍计入已执行的想象计算量。`critic_only_updates` 保留为“未执行 Actor step”的兼容计数，其中可能包含拒绝事件，应结合事件类型阅读。

## 4. 拆开 Actor 放行与 Q 自举切换

新增 `q_keep_teacher=true`，仅允许与 `q_teacher_v=true` 配合。这样 Actor 通过闸门后可以开始更新，Q 标签仍保持：

`target = reward + gamma * bootstrap * frozen_V(next_state, next_goal)`。

它用于检验“开放 Actor”本身的影响，不再同时切到学生 Q 的 Bellman 自举。默认 false 保留既有协议；已有长实验不被重新解释成该模式。

这个模式评价的是使用冻结 V 尾值的一步改进路径，不能冒称等价于当前策略的完整长期 Q。Actor 远离老师后，V 尾值也可能不适配；因此本模式应与偏移约束和独立验证配合。

## 5. 校准可复检、可撤销

`q_calibration.recheck_interval` 默认 0，保持旧的一次通过行为。设为正数后，已通过的 Q 在后续评估点达到该间隔时重新校准：

- 复检失败，`q_calibration_passed` 设回 false，Actor 重新冻结。
- 记录 `last_q_calibration_iteration` 并随检查点恢复。
- 撤销后重置 Q 自举同步标志，未来再次放行时不沿用过期状态。
- 检查仍发生在公共评估点；例如 eval_interval=500，recheck_interval=100，并不意味着每 100 步检查一次。

复检并未扩大原来四个局部状态的覆盖，也不能认证 Q 导数；它修复的是“通过一次永久放行”的控制缺口。已有校准阈值不自动放宽。

## 6. 原 SuperMimic 原生恢复入口

新增 [validate_native_resume.py](../scripts/validate_native_resume.py)。它读取原检查点配置，使用真正的 `Trainer.load()` 恢复 Actor、WM、V、三类 Adam、采样器和迭代数；不经 `make_config()` 的对照协议覆盖。

只修改路径、设备和输出目录。环境数、Actor/WM batch、H、WM 批次数等保留原值。`Trainer.run(stop_iteration=...)` 新增可选停止点，以便短测时仍保持原 schedule.total_iterations=320000，而不是将余弦时间表压缩到短测步数。

已验证本地原模型迭代为 51350，计划运行 200 个额外向量步时停止在 51550，原学习率时间表和配置保持不变。

先生成计划，不启动仿真：

```bash
uv run --extra train --locked python scripts/validate_native_resume.py \
  --checkpoint "$CHECKPOINT" --motions "$MOTIONS" \
  --output outputs/native_resume_plan_v1 --steps 200 --dry-run
```

正式短验证需选择新输出目录并去掉 `--dry-run`。`--eval-max-steps 0` 才是完整动作评估；默认 200 仅用于链路检查。必须使用对应的原动作文件和顺序，改路径不代表数据已证实一致。

原生 4096 环境、H=32、batch=2048 的内存需求明显高于本次小测试，因此本次仅检查配置与恢复入口、运行停止逻辑，尚未声称已在本机完成原生训练表现验证。恢复后 replay/仿真状态需要重新建立，不能声称与未中断训练逐位一致；共享终止标签修复仍然生效。

## 7. 验证范围

- `tests/test_actor_safety.py`：覆盖有界均值漂移、回退只提交一次 Adam、拒绝后参数和动量精确恢复、非有限候选拒绝、保持 V 监督、校准撤销与恢复、拒绝 BPTT 的真实计算计数。
- `tests/test_native_resume.py`：覆盖不覆盖原配置、不压缩学习率时间表、拒绝缺少优化器的权重检查点。
- 原有数据记录、随机策略、Q/V、BPTT、融合和编译反传回归继续执行。
- GPU 编译模式短验证使用 [actor_guard_smoke.json](../configs/experiments/actor_guard_smoke.json)，三种方法各 80 步、单动作、16 环境；**刻意关闭校准闸门以覆盖防护后的 Actor 更新**，这不是 Q 已成熟的证据，不能用此配置启动正式科研长实验。
- 短验证只检查实际仿真、编译反传、计数、目标来源和更新回退，不证明 40 动作长期成绩恢复。

记录保存在 `outputs/stability_repair_20261107/`。最新四组的失败与成绩保持原样，没有因代码修改而重写历史结果。

## 8. 本次实际验证结果

使用项目要求的 Python 3.12 缓存训练环境，全套 CPU 回归 **61 passed**。第一次用系统 Python 3.10 执行时，有一项原有数据准备测试因 `hashlib.file_digest` 不存在而失败；切换到项目要求的 Python 3.12 后通过，没有为此修改数据准备逻辑。

RTX 4060 上使用正式 `compile=default` 跑完三个单动作、各 80 步的真实仿真：

| 方法 | 实际 Actor 更新 | 超限拒绝 | 接受更新最大 RMS 变化 | 相对老师最大偏移 | 第 80 步窗口回报 |
|---|---:|---:|---:|---:|---:|
| Q-only | 10 | 10 | 0.009875 | 0.099858 | 0.952981 |
| V-BPTT | 12 | 12 | 0.008905 | 0.099967 | 0.951625 |
| 固定融合 | 10 | 10 | 0.009077 | 0.099936 | 0.952617 |

三组训练前窗口回报均约 0.955204；均没有提前失败，也均达到 100 步评估封顶。**回报略有下降，不能报告成性能提升或整段动作成功。** 约一半 Actor 尝试被拒绝，说明当前候选梯度会很快触及局部偏移界限；防护能阻止继续越界，但也可能造成学习停滞，不能通过简单放宽界限掩盖这个问题。

检查点审计确认：三个组的冻结 Actor 老师和冻结 V 与原检查点逐项一致；Actor 实际发生了被接受的更新；sigma 保持固定；全部 Q 更新继续使用 V 标签，没有转回学生 Q 自举。BPTT 的想象计算量包含被拒绝的候选更新。审计结果见 `outputs/stability_repair_20261107/integration_checks.json`。

首次 GPU 启动在项目导入阶段退出（缓存环境的源码路径被通用 suite 启动器清除），尚未开始训练；随后使用显式保留源码路径的诊断启动器完成上述三条验证。该环境调整没有修改通用服务器启动器或算法。

结论限于：已经修复可观测动作漂移缺少约束、更新回退缺失、校准永久放行和无法单独保留 V 标签的控制缺口；原生基线恢复入口已完成配置/停止逻辑验证。**原生基线恢复后的表现，以及 40 动作长训练能否稳定改善，仍需后续受控实验。**
