# 四组 5000 步继续训练对照

日期：2026-11-06。四组都从同一个第 51350 步 SuperMimic 检查点独立开始，不串用其他组训练后的模型。Q-only 保持运行，新增独立的固定融合和原基线任务；BPTT 首次尝试因编译反传异常退出，在修复后从相同预训练检查点重新启动。通过 Git 部署到独立检出目录。

## 公共条件

R1、同一 40 段 ModelScope 动作、seed=0、256 环境、5000 个向量步（计划 128 万条训练转移）、H=8、Actor/WM batch=256、每次 WM 更新 2 个 minibatch。每 500 步完整动作评估，初始评估也跑完整时长。Actor 起始学习率均为 2e-5，WM 仍为 2e-4。

| 方法 | Actor 更新 | 末端值与新增 Q | 预热/校准 |
|---|---|---|---|
| supermimic | 原均值 BPTT | 加载原 V，沿原 GAE 路径更新 V | 无新增 Q |
| q_only | Q 梯度 | V 监督新 Q，放行后转普通 Bellman | 至少 400 次 Q 更新＋局部校准通过 |
| bptt_soft（V 验证版） | 固定方差的随机 BPTT | 固定原 V；旁路 Q 不影响 Actor | 不依赖 Q 就绪 |
| dual_fixed（V 验证版） | 固定 0.5/0.5 的 Q＋随机 BPTT | BPTT 使用固定原 V；Q 同 Q-only 培养 | 至少 400 次 Q 更新＋同样校准 |

三个随机组固定 sigma=exp(-2.3)≈0.1003、alpha=0；这一轮验证不含可学习探索方差或最大熵目标。原基线保留自身额外执行噪声和 clean-action 历史语义，原 V 也继续更新；因此四组是明确条件下的机制对照，不应宣称所有组只差一个融合系数。

原基线的 Actor 与 V 学习率一起缩放到原配置的 0.1，以匹配原 PolicyTrainer 将两者按相同时间表设置的行为；其他组 Q 仍使用初始 lr=3e-4。预算和实际优化次数都须记录，不能把相同交互预算称为相同计算量。

## 固定融合的单位

Q-only 使用 J_Q；V 末端 BPTT 使用 J_B/H，与原 SuperMimic 的时域归一化一致。因此融合为：

`g = 0.5 * grad(J_Q) + 0.5 * grad(J_B / H)`。

两个目标在同一个 Actor 参数快照上求导，初始动作样本共享；只执行一次 Actor optimizer step。最终执行全局范数裁剪，V 端点路径保留逐元素裁剪。没有按梯度范数动态配权；0.5 系数不代表两条梯度范数相等，日志仍记录二者范数和余弦。

Q 尚未就绪时，融合组整个 Actor 冻结，保持固定比例融合的起点；不是先偷偷训练 BPTT 再切到融合。校准通过后才开始固定融合，Q target 在首次转 Bellman 时与已预热在线 Q 同步一次。

## 配置与验证

- `supermimic_matched_5000.json`：学习率对齐的原 SuperMimic。
- `q_only_v_teacher_5000.json`：已经运行的 V 监督 Q-only。
- `bptt_v_teacher_5000.json`：已经运行的 V 末端随机 BPTT。
- `dual_fixed_v_teacher_5000.json`：加入 Q 预热和校准闸门的固定融合。
- `dual_fixed_v_teacher_smoke.json`：仅用于验证融合计算链，4 次预热后执行少量融合更新；刻意关闭校准闸门，不能作为 Q 成熟的证据或正式长训练协议。

CPU 回归覆盖混合分支的校准冻结、梯度单位、真实 Q/模型/V 计算图上的一次固定融合更新，以及基线学习率配置。GPU 冒烟验证两条梯度都存在、融合权重始终为 0.5、V 和老师 Actor 不变，以及实际 Actor 更新发生。

纯分支跳过权重为零的目标求导。纯 V-BPTT 的占位 Q 目标与 BPTT 共享图，旧实现先对占位目标使用 `retain_graph=True`，触发 CUDA 编译反传的 donated-buffer 限制。修复后该路径仅反传一次；GPU 冒烟须使用 `--compile default` 覆盖正式训练配置。

## 并行执行与结果解释

四个进程在同一张 L40 运行，使用独立结果目录和 tmux 会话。新增的基线、融合和重启 BPTT 共用修复后的只读源码及 Python 环境；Q-only 保留其原源码快照。

显存允许并不意味着并行任务一定更快；GPU 利用率已接近满载时会共享计算资源。各进程 wall time、全卡功率和全卡显存受到其他组影响，不用于孤立的计算效率/能耗比较。任务表现、训练转移数、Actor/Q/WM 实际更新数和校准阶段分别报告。

四组最终必须保留未完成、超时、校准未通过的状态。Q 校准未通过时 Actor 没有更新，不能将其作为“融合有效/无效”的直接证据。各组仍只有一个种子，不做稳定性或统计显著性结论。
