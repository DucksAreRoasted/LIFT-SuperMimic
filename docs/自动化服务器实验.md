# 一次启动 R1／LAFAN 对照实验

入口是 `scripts/launch_research.py`。它只依赖 Python 标准库，启动时通过 uv 安装统一训练环境，然后准备数据、跑冒烟、顺序训练四种方法并汇总结果。正式训练由服务器执行。

## 默认运行

在服务器项目根目录执行：

```bash
python3 scripts/launch_research.py --gpu 0 --output outputs/r1_pilot_01
```

默认使用本项目已准备好的路径：

- `data/checkpoints/r1_supermimic_pretrained.pt`
- `data/retarget/lafan1_modelscope_v1/r1/`

如服务器已有旧仓库数据及检查点，只需一次调用：

```bash
python3 scripts/launch_research.py \
  --checkpoint /server/old_project/logs/r1_lafan1/ckpt_latest.pt \
  --data-source /server/old_project/data/retarget/lafan1_modelscope_v1/r1 \
  --gpu 0 --output outputs/r1_pilot_01
```

已有数据会复制到当前项目默认动作目录；检查点直接读取你指定的文件。若没有重定向数据，用 `--download-data` 替换 `--data-source`，另行提供已有 R1 预训练检查点即可。源码、第三方模型、uv 和可用的单张 NVIDIA GPU 需要已在服务器上，uv 依赖安装和数据下载需要网络。

本次服务器部署按用户要求从 **ModelScope** 获取数据，使用：

```bash
python3 scripts/launch_research.py --download-data \
  --dataset-id AI-ModelScope/LAFAN1_Retargeting_Dataset \
  --dataset-revision master \
  --checkpoint /server/path/existing_r1_checkpoint.pt \
  --gpu 0 --output outputs/r1_modelscope_pilot_01
```

该来源提供既有清单的 G1 参考 CSV，程序再通过原复现的重定向流程生成 R1 的 50 Hz NPZ；不是把 G1 数据直接用于 R1 训练。仍只处理固定 40 段子集。ModelScope 数据下载不经过 GitHub 镜像；GitHub 代理只用于仓库和 mjlab 等 Git 来源。可叠加前述 `--github-mirror` 或 `--github-proxy`。

`network.json` 保存本次请求的数据集 ID／版本，原准备流程另存下载文件哈希、重定向记录及数据清单；`master` 是可变分支，后续复现优先指定已确认可用的固定 revision。已有 R1 预训练检查点仍需单独提供。

默认在独立 tmux 会话中后台启动，SSH 断开后继续执行；服务器需要安装 tmux。启动输出包括会话名、结果目录和总日志位置。命令参数和日志路径均做 shell 引用处理，支持路径中的空格。`launcher.json` 保存会话名，`pipeline_status.json` 保存实际 worker PID。

可以用 `tmux attach -t <会话名>` 查看会话，用 `Ctrl-b` 再按 `d` 脱离会话。任务结束后会话退出，状态与日志仍在磁盘。没有 tmux 时脚本会明确报错；只有显式指定 `--background-backend process` 才使用普通后台进程。

## 下载索引与 GitHub 代理

`pyproject.toml` 与 `uv.lock` 已使用华为云镜像。当前锁文件的普通包下载地址全部为 `repo.huaweicloud.com`；CUDA Torch 的 wheel 使用 `download-r2.pytorch.org`，Warp 的 wheel 使用 `pypi.nvidia.cn`，mjlab 使用 GitHub 的固定提交。服务器安装前需要实际确认这些地址可达，华为镜像不代表所有依赖都走同一域名。

GitHub 支持两种方式，二选一：

```bash
# GitHub 镜像 URL 前缀（示例占位地址，需换成服务器上实测可用的服务）
python3 scripts/launch_research.py \
  --github-mirror https://your-mirror/https://github.com/ \
  --gpu 0 --output outputs/r1_pilot_01

# 或服务器可达的 HTTP/SOCKS 代理
python3 scripts/launch_research.py \
  --github-proxy http://proxy-host:port \
  --gpu 0 --output outputs/r1_pilot_01
```

也可提前设置 `TADG_GITHUB_MIRROR` 或 `TADG_GITHUB_PROXY` 环境变量。启动器会在依赖安装前测试 mjlab 的 GitHub 访问，超时 90 秒则停止，避免后续一直等待。

代理配置通过进程级 Git 配置传递给 uv 的 Git 子进程，仅处理 GitHub，不修改全局 Git 配置，不改变 mjlab 提交号或 `uv.lock`。HTTP/SOCKS 方式只设置 GitHub 对应的 Git HTTP 代理，不让华为云索引绕道代理。具体代理是否支持 Git clone 需在服务器验证，不能只用浏览器能打开网页来判断。

首次克隆本项目发生在启动器运行之前，也要配置相同代理。例如镜像模式可这样克隆（实际部署由助手在获得 SSH 后执行）：

```bash
export TADG_GITHUB_MIRROR=https://your-mirror/https://github.com/
git -c "url.${TADG_GITHUB_MIRROR}.insteadOf=https://github.com/" \
  clone https://github.com/DucksAreRoasted/LIFT-SuperMimic.git \
  /absolute/gpufreedata/LIFT-SuperMimic
```

不预设未经验证的公共代理地址。获得服务器后先测试可用代理，再用同一配置完成项目克隆与 mjlab 安装。

## 自动执行的内容

1. `uv sync --extra train --locked`，安装基线和 TADG 共用环境。
2. 导入／校验 R1 的 LAFAN 数据，生成逐文件 SHA-256 清单。
3. 原基线与双梯度各一次短冒烟：48 步、16 环境、单动作。
4. `supermimic`、`q_only`、`bptt_soft`、`dual_fixed` 顺序执行：每组 5,000 步、256 环境、种子 0，即每组 128 万训练转移，四组合计 512 万。
5. 每组从同一个原预训练检查点重新开始；不会串用上一方法的训练结果。
6. 在初始状态及每 1,000 步，对 40 个动作做完整时长评估；保存逐动作结果、误差、轨迹、梯度、资源、模型及汇总。

同一张 GPU 上顺序执行，避免四组争抢显存。默认完整评估可能较耗时，计入单独的评估成本。未给方法设置墙钟截止时间，以免不同速度的方法被截成不同训练预算。任一步失败，停止后续阶段并保留日志；不会自动反复重试耗费算力。

这些评估动作与训练动作重合，用于继续训练机制比较，不是未见动作泛化。当前算法仍是固定权重融合；可信度和自适应时域尚未接入。

## 查看进度与结果

```bash
python3 scripts/launch_research.py --status --output outputs/r1_pilot_01
tail -f outputs/r1_pilot_01/pipeline.log
tail -f outputs/r1_pilot_01/pilot/seed_0/dual_fixed/console.log
```

`pipeline_status.json` 记录当前阶段及整体完成／失败状态；`pilot/suite_progress.json` 记录已结束的方法。总日志记录调度阶段，训练细节在各方法的 `console.log` 中。

```text
outputs/r1_pilot_01/
  plan.json                    完整执行命令和预算
  protocol_smoke.json
  protocol_pilot.json          本次冻结配置
  launcher.json                后台 PID 与命令
  pipeline_status.json
  pipeline.log
  smoke/                      两组冒烟记录
  pilot/
    summary.csv
    evaluation_curves.csv
    aggregate.json
    seed_0/
      supermimic/
      q_only/
      bptt_soft/
      dual_fixed/
```

结果目录必须是新目录。失败后不会自动续跑或覆盖，修复后换一个输出目录重新启动。后台脚本可以承受 SSH 断开，不能跨服务器重启恢复。

## 后续三种子实验

看完初步结果后再显式运行：

```bash
python3 scripts/launch_research.py --stage confirm \
  --gpu 0 --output outputs/r1_confirm_01
```

这会从同一个原始预训练检查点开始四组 × 三种子（0／1／2），每组 20,000 步、256 环境，评估间隔 5,000 步。不是接着 pilot 的模型训练。总训练转移为 6,144 万，不含独立评估；默认命令不会启动这一阶段。

`--stage all` 才会自动连续完成初步及三种子实验；它不会根据 pilot 分数判断研究方向。`--skip-smoke` 跳过冒烟，`--no-sync` 跳过环境安装，`--foreground` 保持前台执行。已由外部 tmux 会话托管时可用 `--foreground`，避免嵌套会话。

只生成完整计划，不安装依赖、不下载、不启动训练：

```bash
python3 scripts/launch_research.py --dry-run --output outputs/r1_plan_01
```

本次已做无 GPU 的调度测试和计划生成测试；5,000／20,000 步自动化流程尚未实际执行。此前 R1 基线／双梯度 GPU 冒烟结果见[实测记录](R1_LAFAN冒烟结果_20261105.md)。

## 交给助手启动服务器

提供 SSH 连接方式（主机／用户名／端口，或已配置的 SSH 别名）、服务器项目路径、可用 GPU 编号、已有 R1 检查点和数据目录即可。使用现有密钥／SSH 代理认证；若需要交互认证，再按实际连接提示处理，不必在聊天里发送密码或私钥。

耗时估计在服务器测量后给出：环境安装／数据传输单列，训练用最初 100～200 步的稳态更新速度推算，并加入 40 个动作的完整评估耗时与首次编译时间。不能直接用此前 16 环境、20 步封顶评估的本地冒烟时间估算 256 环境的正式对照。若安装依赖受网络限制，先报告安装瓶颈，再更新训练 ETA。
