# Q-only 修复冒烟结果

日期：2026-11-06。**真实 GPU 冒烟通过，当前关注的修复项均得到验证。** 本次没有启动 5000 步长训练。

## 测试条件

- GPU：本地 NVIDIA GeForce RTX 4060 Laptop，8 GB。
- 环境：Python 3.12.14、Torch 2.14.1+cu130、MuJoCo 3.16.0、Warp 1.18.0，mjlab 使用项目锁定提交 `8bb2bc9` 的缓存源码。
- 检查点：旧仓库 `logs/r1_lafan1/ckpt_latest.pt`，SHA-256 为 `9f6a55c37eb792c4e407ac7b1fba545723b884f1c217bf385d77e0f574a2978f`，与首轮服务器预训练起点完全相同。
- 动作：本地 `lafan1_official_v1/r1/walk1_subject1.npz`。其 SHA-256 为 `f2eb9ed3b2f9be85590dae3776c841969596b001f0df9cb0b0d81ea7a4bb9293`，与服务器 ModelScope 版本文件不同，不能据此直接横比任务得分。
- 16 个环境，80 个向量训练步，replay 填充 20 步，Q-only 独立预热 4 次 Q 更新，固定 sigma≈0.10025884，Actor 学习率乘 0.1。
- 为覆盖边界，将训练 episode 上限设为 0.5 秒；训练结束后额外执行 2 次诊断环境步，其中人为注入一次摔倒。这些诊断步没有进行 Q/Actor 更新。
- 使用已有只读依赖缓存组装隔离环境，没有修改旧环境、下载依赖或修改算法代码来适配运行环境。

## 修复项逐项结果

| 检查项 | 实际验证方式 | 结果 |
|---|---|---|
| Q 预热时 Actor 保持不变 | 每次 critic-only 更新后，将全部 Actor 参数与初始快照逐张量精确比较，检查 Actor optimizer 尚无状态 | 4 次均通过 |
| Q 在预热中确实训练 | 对比 Q 参数与初始化快照 | Q 已变化 |
| 预热结束后才更新 Actor | 日志前 4 次事件为 critic_warmup；第 32 步开始 actor_update；最终检查 Actor 参数变化 | 通过，20 次 Actor 更新 |
| 固定方差 | 对真实采集、Q target 和 Actor 更新中的每次 sample 检查全部 std 元素，而非仅均值 | 正常路径 128 次、恢复路径 84 次通过 |
| 固定方差仍可更新均值 | GPU 路径 Actor 参数发生变化，std head 无梯度；CPU 回归另检查重参数化均值梯度 | 通过 |
| Actor/Q 学习率分别正确 | 每次更新检查 Q lr 与缩放后 Actor lr 的比例，CPU 回归检查实际 set_lr 数值 | 通过，比例 15 |
| 摔倒前一步不提前关闭 bootstrap | 对真实 recorder 写入的数据调用真实 sample_real_batch | bootstrap=1 |
| 真正摔倒转移关闭 bootstrap | 注入摔倒并确认环境 terminated，再对实际最后转移调用真实 sampler | bootstrap=0 |
| 普通超时保留 bootstrap | 缩短 episode 触发真实超时，对真实超时转移调用 sampler | bootstrap=1 |
| 参考动作结束关闭 bootstrap | CPU 回归调用真实 recorder、ReplayBuffer 和 sampler 构造该边界 | 通过；本次未额外注入 GPU 参考结束场景 |
| Replay 非 terminal 状态标签 | 扫描两条 GPU 路径的全部有效非 terminal 行 | 错误 done 标签均为 0 个 |
| 检查点保存恢复预热进度 | 第 24 步保存 q_updates=2、actor_updates=0 的真实检查点，重新建立训练器并恢复 | 只补做剩余 2 次预热 |
| 日志计数 | 对比实际执行检查与 recorder counters | Actor、critic-only、Q 计数一致；想象步数为 0 |
| 数值有效性 | 检查最终 Actor/WM/Q 参数和有效 replay 状态 | 全部有限 |
| Q 非有限目标拒绝更新 | CPU 回归注入 inf target 并检查 Q 参数未改变 | 通过 |

## 实际运行计数

| 路径 | 新执行向量步 | WM 更新 | Q 更新 | 仅 Q 预热 | Actor 更新 |
|---|---:|---:|---:|---:|---:|
| 正常运行，0→80 | 80 | 24 | 24 | 4 | 20 |
| 从预热检查点恢复，24→80 | 56 | 14 | 14 | 2 | 12 |

恢复时读取的累计 Q 更新数为 2；恢复路径结束后累计为 16，累计 Actor 更新为 12。表内的 Q 更新 14 是本次恢复运行新增次数。

正常路径在第 22、24、27、29 步执行 critic-only；第 32 步首次更新 Actor。恢复路径在第 46、48 步补完预热，第 51 步首次更新 Actor。恢复时仍按原循环重新填充 replay，因此不会立即沿用旧 buffer。

正常路径的实际 replay 中包含 50 个 terminal 行，其中 1 个为人为触发的真摔倒；恢复路径有 33 个 terminal 行，全部不是实际摔倒终止。事件中的 timeout 次数包含诊断步，不应换算成任务失败率。

## 短窗口评估

正常路径 step 0、40、80 的行走评估均执行到 100 步封顶，没有摔倒；每步归一化回报约为 0.9552、0.9571、0.9541。恢复路径的三个评估点同样未摔倒、均封顶。

**100 步只对应 2 秒，不能称为完整动作成功，更不能证明 5000 步后不会退化。** 本次主要结论是修复行为在真实训练链中生效，尚未验证长期 Q 校准或完整任务收益。正式配置的 Q 预热预算是 400 次，本次用 4 次验证阶段切换和恢复逻辑。
